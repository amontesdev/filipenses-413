# Security Policy

## Supported Versions

This project is in active development. Security fixes, when available, are expected to land on the latest version under active maintenance.

## Reporting a Vulnerability

Please do not open a public GitHub issue for security vulnerabilities.

Instead, report vulnerabilities privately to the maintainer with:

- a clear description of the issue
- steps to reproduce it
- impact assessment, if known
- any suggested mitigation or fix

If the report is valid, the goal is to acknowledge it promptly, investigate the issue, and coordinate a fix before public disclosure when possible.

## Scope

Security reports are especially helpful for issues involving:

- authentication and authorization
- Supabase policies or data exposure
- secret encryption and decryption flows
- insecure defaults in setup or deployment
- sensitive data leakage in logs, responses, or UI

## Sensitive Data

Do not include production secrets, private keys, tokens, or personal user data in reports.
